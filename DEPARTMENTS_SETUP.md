# Отделы и личные исключения

## Активация (только после отдельного разрешения)

Новая версия сама не создаёт таблицы отделов при старте. До активации
существующие пользователи сохраняют прежние права. Вкладка отделов сообщает,
что требуется обновление базы.

Остановите приложение на время обновления. Из папки проекта, используя
Python окружения приложения, выполните:

```text
python scripts/migrate_departments.py --database /абсолютный/путь/requirements.db --apply
```

Скрипт создаёт согласованную резервную копию SQLite рядом с базой и две новые
таблицы. Прежние таблицы и права не изменяются. Повторный запуск безопасен.
Резервную копию не загружать в GitHub: в ней данные пользователей.

## Правила

- Управляют отделами администраторы. Администраторы сохраняют полный доступ.
- У сотрудника один отдел. Назначение другого заменяет прежний.
- Личный запрет или разрешение важнее прав отдела.
- Разрешение объекта не открывает закрытый раздел «Подбор объектов».
- «Все объекты» распространяется и на новые объекты; глобально скрытые
  объекты по-прежнему скрыты подбором.
- При назначении или смене отдела всегда применяются права нового отдела,
  прежние личные исключения сбрасываются. Выбирать режим не требуется.
- Удаление из отдела сохраняет текущие доступы как личные настройки.
- Кнопка «Использовать только права отдела» сбрасывает личные исключения
  у сотрудника, который уже состоит в отделе.
- Доступ в админ-панель не повышает роль. Менеджер с ролью viewer не получает
  полномочий управлять пользователями; руководитель сохраняет свои ограничения.
- Старое окно с галочками не сохраняет права сотрудников, переведённых на отделы.

## Ручная проверка после активации

1. Войти администратором, открыть «Админ-панель → Отделы и исключения».
2. Создать отдел, разрешить подбор и один объект.
3. Назначить тестового сотрудника в отдел.
4. В отдельном сеансе проверить меню, доступ к объекту и его паспорту.
5. Добавить личный запрет объекта: объект и его паспорт должны стать недоступны.
6. Вернуть «Как у отдела»: объект снова доступен.
7. Запретить раздел: прямой URL раздела также не должен открываться.
8. Перевести сотрудника в другой отдел: прежние разрешения не должны сохраниться.
9. Изменить права отдела: пользователи без исключений получают новые права.

Автотесты используют только базу в памяти, без импорта рабочего приложения:

```text
python -m unittest discover -s tests -p "test_department_permissions.py" -v
```
