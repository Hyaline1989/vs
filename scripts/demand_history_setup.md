# История потребности

Файлы обновления:

- demand_history.py
- scripts/migrate_demand_history.py
- database/requirements.py
- routes/requirements_admin.py
- routes/service_reports.py
- templates/service.html
- static/rotation_duration.js
- static/demand_history.js

Перед запуском обновлённого приложения выполнить миграцию. Без неё сохранение потребности будет отменяться целиком, чтобы не терять историю.

Локально, при остановленном приложении, из папки проекта:

```powershell
.\venv\Scripts\python.exe scripts/migrate_demand_history.py --database requirements.db --apply
```

На сервере: остановить vs-complect, загрузить файлы, из папки проекта выполнить:

```bash
./venv/bin/python scripts/migrate_demand_history.py --database requirements.db --apply
sudo systemctl start vs-complect
```

Миграция создаёт резервную копию рядом с базой, добавляет только demand_history и не меняет старые таблицы. Повторный запуск не удаляет историю. Не заменять серверную базу локальной.

Архив записывается при сохранении текущих потребностей и при обнулении объекта, в той же транзакции. День определяется по Москве. Сумма шести полей считается как в существующем дашборде. Приоритеты берутся из daily_snapshots, а не текущей галочки. История не удаляется плановой очисткой vacancy_requirements. Дни без сохранения остаются пустыми, прошлые максимальные потребности не импортируются. Изменение названия создаёт отдельную строку истории; старое название сохраняется.

Проверка: сохранить потребность 10, затем 6 за тот же день — в VIP должно быть 6. Сохранить 0 — должно быть 0. За день до включения архива — «—». После фиксации приоритетов обновить отчёт кнопкой «Показать». Пользователь без VIP не должен получать API /api/service/demand-history.
